# Dock — мобильное приложение для крупногабаритных перевозок

Промежуточная версия **0.6** (этап лекции 6): работающая база данных и API на Supabase, слой
репозиториев, сервисов и DTO, экраны по паттерну MVVM. Приложение соответствует документам
**Vision** и **SAD**; отличия от них и предложения по правкам собраны в [`docs/SAD-changes.md`](docs/SAD-changes.md).

Стек (SAD, раздел 2): TypeScript · React Native (Expo SDK 58, Expo Router) · Supabase (PostgreSQL, Auth,
Storage, RLS) · `@supabase/supabase-js` · zod.

## Запуск

```bash
npm install
cp .env.example .env      # URL и publishable-ключ проекта Supabase
npm start                 # QR-код для Expo Go (iOS/Android)
npm run web               # или в браузере — удобно для показа на ноутбуке
```

Проверка типов: `npm run typecheck`.

### Подготовка демо

1. **Подтверждение email.** В новом проекте Supabase оно включено: после регистрации придёт письмо.
   Для демо его удобно выключить: Dashboard → Authentication → настройки провайдера Email →
   переключатель *Confirm email*.
2. **Верификация водителя (UC-02).** Веб-панели администратора пока нет, поэтому документы
   подтверждаются SQL-запросом в Dashboard → SQL Editor:
   ```sql
   update public.users set is_verified = true where email = 'driver@example.com';
   ```
3. Сценарий для показа: заказчик создаёт заявку → водитель (верифицирован, с добавленным ТС) видит её в
   ленте и откликается со своей ценой → заказчик выбирает исполнителя и оплачивает (демо-эскроу) →
   водитель отмечает «Прибыл на погрузку», делает фото, «В пути», «Прибыл на выгрузку», фото →
   заказчик подтверждает приёмку → обе стороны оставляют отзыв.

## Архитектура (MVVM + репозитории + сервисы + DTO)

```
View (экран)  →  ViewModel (хук)  →  Service  →  Repository  →  supabase-js  →  Supabase
   src/views        src/viewmodels     src/services   src/repositories   src/core/supabase.ts
                         ↑                  ↓
                     DTO (src/models/dto.ts) ← mappers.ts ← строки БД (database.types.ts)
```

| Слой | Папка | Что делает |
|---|---|---|
| Маршруты | `src/app` | Тонкие файлы Expo Router: связывают URL с экраном, без логики |
| View | `src/views/screens`, `src/views/components` | Только отображение и передача действий во ViewModel |
| ViewModel | `src/viewmodels` | Состояние экрана, валидация форм, вызов сервисов (SAD 5.2: `AuthViewModel`, `OrderViewModel`, `TrackingViewModel`) |
| Service | `src/services` | Бизнес-логика сценариев, преобразование строк БД в DTO |
| Repository | `src/repositories` | Все запросы к Supabase; одна сущность — один репозиторий |
| Models | `src/models` | DTO, доменные правила (`domain.ts`), схемы валидации zod (`schemas.ts`), справочники |

**Сервисы (7):** `AuthService`, `OrderService`, `BidService`, `TrackingService`, `VehicleService`,
`ProfileService`, `ReviewService`.
**Репозитории (8):** `AuthRepository`, `UserRepository`, `VehicleRepository`, `OrderRepository`,
`BidRepository`, `PhotoRepository`, `ReviewRepository`, `StorageRepository`.

### Материал лекции 6

- **N+1 и жадная загрузка.** Карточка заказа загружается одним запросом со всеми связями
  (`OrderRepository.getOrderDetails`): заказчик, водитель, отклики → водители → их ТС, фото, отзывы.
  PostgREST делает JOIN по внешним ключам — аналог `joinedload`. Рейтинги всех водителей из
  откликов приходят одним запросом `target_id IN (...)` (`ReviewRepository.getRatings`) — аналог
  `selectinload`; подписанные ссылки на фото — тоже одним запросом. Итого 3 запроса на карточку
  независимо от числа откликов.
- **DTO.** Экраны получают только DTO (`src/models/dto.ts`): camelCase, тонны вместо килограммов,
  без служебных полей. Преобразование — в `src/models/mappers.ts`.
- **Схемы валидации** (аналог Pydantic) — zod в `src/models/schemas.ts`.
- **Сервисный слой** — проверки сценариев (`canCancel`, `checkCompatibility` …) до запроса в сеть.

## Реализованные сценарии (Vision, раздел 5)

| UC | Сценарий | Где |
|---|---|---|
| UC-01 | Пройти верификацию документов | Профиль → «Пройти верификацию» (фото паспорта, ВУ, СТС в Storage) |
| UC-03, 04 | Создать заявку, габариты и вес | Вкладка «Создать»: тип груза иконками, Д×Ш×В, масса, подсказка про негабарит |
| UC-05 | Точки маршрута | Пока адресами; выбор на карте — следующий этап |
| UC-06 | Выбрать исполнителя | Карточка заявки → отклики с рейтингом и ТС → «Выбрать» (атомарная RPC `accept_bid`) |
| UC-07 | Отменить заявку | Карточка заявки, с причиной |
| UC-08, 09 | Лента заявок с фильтром по ТС | Вкладка «Поиск грузов»; фильтр по массе и габаритам выполняется в БД |
| UC-10, 11 | Отклик и встречная цена | Карточка заявки (водитель): «Откликнуться за …» или своя цена с комментарием |
| UC-12, 13 | Оплата и заморозка средств | Экран рейса → «Оплатить» (**демо**: флаг `is_escrow_locked`, без платёжного шлюза) |
| UC-14 | Перевод средств исполнителю | При приёмке триггер снимает блокировку (демо) |
| UC-15 | Смена статуса рейса | Экран рейса: «Прибыл на погрузку» → «В пути» → «Прибыл на выгрузку» |
| UC-16 | Отследить статус | Экран рейса: шкала этапов (без GPS-карты) |
| UC-17 | Фотофиксация | Экран рейса: фото погрузки/выгрузки — обязательны для перехода дальше |
| UC-18 | Подтвердить приёмку | Экран рейса (заказчик) — после фото выгрузки |
| UC-19 | Отзыв и оценка | Экран рейса после завершения; рейтинг виден в откликах и профиле |

**Отложено на следующие этапы:** карта и GPS-трекинг (UC-05, UC-16), реальный платёжный шлюз
(UC-12–14), споры (UC-20, UC-21 — таблица и RLS уже есть), веб-панель администратора (UC-02, UC-22),
спецразрешения (UC-23), push-уведомления.

## База данных

Миграции — в [`supabase/migrations`](supabase/migrations), уже применены к проекту `xvkimvpcrfsspyntalmg`:

| Файл | Содержание |
|---|---|
| `20260927000000_initial_schema.sql` | Исходные 7 таблиц (восстановлены по проекту) |
| `20261026000100_extend_schema.sql` | Тип и описание груза, причина отмены, комментарий к отклику, тип/модель ТС, отзыв от обеих сторон, индексы, `updated_at`, автосоздание профиля при регистрации |
| `20261026000200_business_rules.sql` | Статусная модель заказа в триггерах, проверки отклика (верификация, габариты ТС), RPC `accept_bid` |
| `20261026000300_row_level_security.sql` | RLS на всех таблицах |
| `20261026000400_storage.sql` | Приватные бакеты `documents` и `order-photos` с политиками |
| `20261026000500_revoke_anon_helpers.sql` | Служебные функции недоступны анониму |

Бизнес-правила продублированы в БД, поэтому их нельзя обойти прямым REST-запросом: например, водитель
не может начать рейс до оплаты, перейти в «В пути» без фото погрузки, а заказчик — сам себе назначить
исполнителя.
