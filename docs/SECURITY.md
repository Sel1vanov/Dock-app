# Безопасность (кейс 6)

| Требование | Как сделано | Где |
|---|---|---|
| Регистрация и вход через API с проверкой полей | `POST /auth/register`, `POST /auth/login`; схемы проверяют обязательные поля, формат email и телефона, пароль ≥ 8 символов с буквой и цифрой, **подтверждение пароля** (`passwordConfirm`) | `server/src/schemas/auth.ts`, `server/src/routers/auth.ts`; в клиенте те же правила до запроса — `src/models/schemas.ts` |
| Нет повторной регистрации | один email и один телефон — один аккаунт: проверка сервисом (409 с указанием поля) **и** уникальные ограничения `uk_users_email`, `uk_users_phone` в БД; email приводится к нижнему регистру (`ck_users_email_format`), телефон — к виду `+7XXXXXXXXXX`, поэтому другое написание того же номера не проходит. Заблокированный пользователь не может завести второй аккаунт на свой email или телефон; занять чужой телефон через профиль тоже нельзя | `services/AuthService.ts`, `services/UserService.ts`, `models/User.ts` |
| Нельзя выдать себя за сотрудника | имена «Администратор», «Поддержка», «Модератор», «Служба безопасности», «Гарант», Dock и т. п. запрещены при регистрации и изменении профиля (422). Сравнение идёт по «скелету» слова: регистр, замена букв цифрами и знаками (`adm1n`, `@dmin`), буквы-двойники из другого алфавита (`аdmin` с русской «а»), разделители внутри слова и буквы через пробел обходом не считаются | `server/src/core/reservedNames.ts` |
| Хранится только хеш пароля | `bcryptjs`, cost 12; своя криптография не пишется. Пароли (в т. ч. текущий и новый при смене) нигде не логируются (`redact`) | `server/src/core/security.ts`, `server/src/app.ts` |
| Подписанный токен с ограниченным сроком | JWT HS256, `exp` = 1 час (`JWT_EXPIRES_IN`), `iss`/`aud`; на каждом защищённом запросе проверяются подпись, алгоритм, издатель, аудитория и срок | `core/security.ts → verifyAccessToken`, `dependencies.ts → authenticate` |
| Продление сессии | чтобы короткий срок токена не заставлял вводить пароль каждый час, приложение само получает новый токен по действующему (`POST /auth/refresh`) — после половины срока и при запуске. Истёкший токен продлить нельзя (час без запросов → вход заново); блокировка и смена пароля проверяются как на любом запросе; в токене хранится время ввода пароля (`sst`), и дольше `SESSION_MAX_AGE` (30 дней) сессия не продлевается | `services/AuthService.ts → refresh`, `src/core/api.ts` |
| Токен в `Authorization: Bearer` | клиент добавляет заголовок в `src/core/api.ts` | `src/core/api.ts` |
| Закрыты все эндпоинты с данными и изменениями | проверка токена подключена ко всей защищённой зоне (`onRequest`), публичны только `/auth/register`, `/auth/login`, `/auth/password-reset-request`, `/health` и выдача файла по **подписанной** временной ссылке | `server/src/routers/index.ts` |
| Смена пароля | `POST /users/me/password`: нужен текущий пароль (неверный → 422), новый проходит те же правила, что при регистрации, и должен отличаться от текущего. Время смены (`users.password_changed_at`) записывается в JWT как версия пароля (`pwv`); токен со старой версией → 401 `TOKEN_EXPIRED`, т. е. все прежние сессии завершаются, а клиент получает новый токен | `services/AuthService.ts → changePassword`, `dependencies.ts → authenticate` |
| «Забыли пароль?» | почтового сервиса в проекте нет: `POST /auth/password-reset-request` отправляет администраторам уведомление, ответ одинаковый для любого email (не раскрывает, кто зарегистрирован), не больше 3 просьб в минуту. Администратор выдаёт временный пароль (`POST /admin/users/{id}/temporary-password`, `crypto.randomInt`), он хранится только bcrypt-хешем, прежние сессии пользователя завершаются; пароль сообщается по телефону из профиля и меняется пользователем | `services/AuthService.ts`, `services/AdminService.ts` |
| Проверка принадлежности записи | чужая заявка, ТС, отклик → 403; фото и все отклики видят только участники; телефоны — только контрагенту назначенного заказа (по ним работают кнопки «Позвонить», WhatsApp, Telegram); документы — только сам водитель и администратор; чужое уведомление → 403; спор открывают только заказчик и назначенный водитель, решает только администратор, текст спора видят только участники и администратор | `services/*Service.ts → getOwned…`, `OrderService.getDetails`, `NotificationService.markRead`, `DisputeService` |
| 401 и 403 | 401 — нет/поддельный/истёкший токен (`TOKEN_EXPIRED`), неверный пароль (одинаковое сообщение для «нет email» и «неверный пароль»); 403 — не та роль, чужая запись, блокировка | `core/errors.ts` |
| Не возвращать пароль, хеш, секреты | ответы собираются явным маппингом и проверяются схемой ответа; `passwordHash` — `hidden`, `lazy` в модели; конфигурация в ответы не попадает | `services/mappers.ts`, `models/User.ts` |
| Секреты в окружении | `JWT_SECRET`, `FILE_URL_SECRET`, `DATABASE_URL` — только в `server/.env` (в `.gitignore`), образец с фиктивными значениями — `server/.env.example`; `npm run env:init` генерирует случайные секреты; сервер не стартует со слабым (< 32 символов) секретом | `core/config.ts`, `scripts/init-env.mjs` |
| Валидация и параметры ORM | все входные данные — через схемы; запросы — через ORM с параметрами, `ILIKE` с экранированием `%`/`_` | `repositories/query.ts` |
| Выход и истечение токена | «Выйти» удаляет токен из SecureStore (Keychain/Keystore; в вебе — localStorage); при 401 от сервера клиент сам удаляет токен и возвращает на вход с сообщением «Срок действия сессии истёк» | `src/core/tokenStorage.ts`, `src/viewmodels/AuthViewModel.tsx` |
| Без traceback и SQL | единый обработчик ошибок отдаёт `{ error: { code, message } }`; детали — только в серверный журнал | `core/errorHandler.ts` |

Дополнительно:

- **Перебор паролей:** не больше 10 попыток входа/регистрации в минуту с одного адреса (`@fastify/rate-limit`, 429);
  при неизвестном email всё равно выполняется сравнение bcrypt — время ответа не выдаёт, зарегистрирован ли адрес.
- **Повышение прав:** роль `Admin` нельзя выбрать при регистрации (422), поменять через `PATCH /users/me` (лишнее
  поле → 422); статус проверки документов меняет только администратор.
- **Заблокированный пользователь** теряет доступ сразу: пользователь загружается из БД на каждом запросе, поэтому
  старый токен перестаёт работать (403).
- **Файлы:** хранятся вне публичного доступа; API выдаёт ссылку `…?expires=…&signature=HMAC` только тем, кому файл
  доступен; подделка или истечение → 403. Принимаются только JPEG/PNG (проверка сигнатуры файла), до 5 МБ.
